# 解码选择

适用版本：`2.2.0-test.6` 测试分支。入口：主页设置 → 解码。选择保存到本机，之后打开的视频使用新设置。

| 选项 | 行为 |
| --- | --- |
| 优先软解 | 高分辨率、高帧率也先尝试软解，忽略先前的避用记录；不因播放较慢自动切换，仅在真实错误或持续无解码进展时恢复到备用路径。 |
| 默认解码 | 根据编码、关键帧间隔、设备解码能力、资源状态和已有播放表现自动选择，不固定软解或硬解优先。已识别的高负担长 GOP 视频优先尝试 Media3 硬解；其他视频保留原生引擎的资源与格式选择策略。 |
| 优先硬解 | 保持硬件优先。已识别的高负担长 GOP 视频先尝试 Media3 硬解；实际失败时保留原生硬解、兼容引擎和必要的软解回退。 |

未设置时采用“默认解码”。三项的保存值沿用 `native_decoder_mode`：默认为 `0`、硬解优先为 `1`、软解优先为 `2`；界面按软解、默认、硬解排列。

## 默认模式的选择范围

高负担长 GOP 条件为已识别的 8-bit SDR AVC/H.264、至少 1080p 像素量、至少 48 fps，以及至少 4 秒的同步帧间隔，覆盖符合这些条件的 1080p/60fps 视频。只读取当前媒体的头部与有界索引，不使用型号、品牌、文件名或文件标识白名单。

该路径只从平台报告为硬件加速且非软件的候选中选择，并由 Media3 按实际格式配置解码器。硬解不存在或初始化、播放实际失败时，使用本次头部与资源决策已确定的原生软解或硬解备选；不会在错误回调中重新猜测，也保留原有兼容引擎回退。迟到的索引结果不替换已经选定的播放器。

未命中该路径时，规格明确的常见 8-bit SDR、最高 1080p/60fps 视频可在内存与温度条件允许时采用原生软解；信息不明、超出范围、资源紧张或已有避用记录时按原有策略选择。显式“优先软解”不进入长 GOP 硬解优先路径。

Media3 1.11.1 在适用的连续向前拖动中复用解码状态，应用以最高约 60Hz 供给最新目标，由引擎合并未完成请求；松手后的最终定位仍使用精准目标。LibVLC 3.7.7 保留原生路径，符合媒体与资源条件时使用有界软件线程配置。默认模式不同时启动多个解码器逐文件测速。

不同编码、参考帧结构、负载和温度仍会影响定位时间，自动选择不代表所有设备和媒体均达到固定延迟。实现与验证范围见 [长 GOP 定位策略](LONG_GOP_SEEK.md)及[完整触摸响应验证](SEEK_RESPONSE_TEST6.md)。此前 `test.4` 的记录见 [解码设置验证](DECODER_SETTINGS_VERIFICATION.md)。

[早期定位对照](SEEK_PERFORMANCE_TEST.md)和[持续定位记录](SEEK_STRESS_TEST.md)属于历史测试包，不替代本版验证，也不能外推为所有设备的性能保证。
