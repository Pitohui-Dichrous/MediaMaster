# 长 GOP 定位策略

本文记录 `2.2.0-test.5` 的通用实现与验证边界。策略依据媒体索引、设备资源和实际输出状态，不使用设备型号、文件名或文件标识白名单。

## 问题与边界

匿名分析样本为 AVC/H.264 High、8-bit SDR、1920×1080、60 fps，使用 CABAC、4 个参考帧和最多 2 帧重排序，关键帧间隔约 10 秒。
精准定位可能需要回到前一关键帧，跨越约 600 帧的范围并处理目标画面的依赖；这不等于必须显示或完整处理其中每一帧。
因此，相同容器格式的定位成本可能明显不同，不能保证所有媒体、所有位置和所有设备都实现零延迟。

## 有界识别

- 只为待播放媒体读取头部和索引；不扫描视频库，不转码或改写媒体。
- 使用 `MediaExtractor` 在时长的 20%、50%、80% 位置查询前后同步样本，最多 3 处，决策等待预算为 150 ms。[同步样本定位 API](https://developer.android.com/reference/android/media/MediaExtractor#seekTo(long,%20int))
- 已知间隔至少 4 秒才认定长 GOP；尾部没有后续关键帧时，使用有效前置关键帧到探测位置的距离作为下界。
- 150 ms 是选择决策与探测检查的预算，不是可强制终止平台 I/O 的硬实时保证。迟到结果进入有界缓存，供后续选择使用，不替换已经选定的播放器。
- 缺失索引、未知格式或读取失败时保留常规策略，不猜测媒体特征。

## 解码选择

高负担候选限定为已识别的 8-bit SDR AVC、至少 1080p 像素量、至少 48 fps，且具有长 GOP。
软件解码时，只有逻辑处理器不少于 8、可用内存和热状态均允许，才请求 8 个解码线程；否则保留原生自动值。
所核对的 VLC 3 原生实现将 H.264 自动线程数限制为最多 6，显式设置可超过此值；帧线程同时增加图片缓冲，因此 CPU 数量不是唯一准入条件。[VLC 线程与缓冲实现](https://github.com/videolan/vlc/blob/84177b2273abc5c4300234e6e18b55a4d2dd5a03/modules/codec/avcodec/video.c#L503-L542)
8 线程只是有条件的并行配置，不代表所有设备都比自动值快；不通过跳过滤波、降低画质或放宽最终定位来换取速度。

文件缓存保留原有的 250 ms，不以缓存配置值推算定位节省的时间。

三种解码偏好保持原有含义：

| 选项 | 本次策略 |
| --- | --- |
| 优先软解 | 不因分辨率、帧率或短暂性能下降改选硬解；实际解码错误或持续无进展才进入故障回退。符合条件时应用软件线程策略。 |
| 默认解码 | 已知普通 8-bit SDR、最高 1080p/60 fps 且资源允许时优先尝试软解；保留实际播放表现反馈与回退。 |
| 优先硬解 | 保持硬件优先及现有兼容路径，不向硬件解码套用软件线程设置。 |

## 输出观察

- 每次提交定位更新 Surface 观察代际。上一请求延迟到达的提交回调不能增加新请求的帧序号，也不能取消新观察。
- 原生解码或显示计数已证明可用后，仅表面回调不能延长无进展监测期限；未查询统计的轮次不视为统计失效。统计一直不可用时，保留表面活动的兼容路径。
- 保留已有的精准定位、请求合并和播放/暂停调度，不增加暂停定位期间的临时播放流程。

输入时钟、Surface 回调和显示计数都不单独证明目标画面的媒体时间戳；旧画面重绘也可能增加显示计数。进展监测用于识别停滞，不能当作逐帧定位准确性的证据。[VLC 输出与重绘实现](https://github.com/videolan/vlc/blob/84177b2273abc5c4300234e6e18b55a4d2dd5a03/src/video_output/video_output.c)

## 验证记录

当前保守基线通过 120 项单元测试、45 项设备回归，以及 10 组持续定位测试；Lint 为 0 错误、36 警告。匿名样本分别覆盖三种解码偏好的播放与暂停状态，公开合成样本以逐帧条码核对定位。各组结束后均核对请求队列、播放器实例及回收状态。

匿名长 GOP 样本在连续操作结束后的最终画面恢复约为：默认/软解 438–573 ms，硬解 779–808 ms。这是固定压力序列最后一次松手后的恢复值，不是全部定位的平均耗时。该基线仍未达到“体感零延迟”目标；后续候选须同时核对首个有效反馈、最终精准画面和连续操作中的停顿，不能只凭提前出现的近似画面宣称完成。

验证区分两种口径：匿名样本采用同一播放器单次定位所得的内容对照，不是独立媒体时间戳真值；公开合成样本使用逐帧条码核对目标和后续轨迹。另行核对解码偏好、同一播放器、最终播放/暂停状态、请求队列和实例回收。

画面变化通过采样观测，不能等同于屏幕的精确呈现时刻。有限序列通过不证明所有媒体零等待，也不能把终点恢复值当作所有定位的平均耗时。
