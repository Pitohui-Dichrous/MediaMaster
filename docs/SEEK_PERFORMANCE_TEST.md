# 定位优化测试版

版本：2.2.0-test.1。分支：`codex/test-seek-performance`。基线：正式版 2.1.0。

## 交互与解码

- 进度条和屏幕横滑共用拖动会话。保持人物控制点、非线性手感和连续的目标位置显示。
- 拖动期间静音，由当前播放器产生画面与小预览，避免另开解码器竞争资源。连续输入只保留最近待处理目标，基础间隔 80 ms；当前请求尚未产生帧时最多等待 180 ms 再替换。
- Media3 使用 scrubbing 模式，拖动中采用前后各 250 ms 的定位容差，松手恢复精确定位。取消回到原位置，保留原播放/暂停状态；系统中断播放后不擅自恢复。
- LibVLC 拖动中使用 fast seek，松手使用精确 seek。媒体级文件缓存显式设为 250 ms，避免 `setHWDecoderEnabled` 补入默认的 1500 ms。缓存数值不是每次定位的固定等待时长。
- 进度栏时间表示手指目标；预览框时间随已获取画面更新（VLC 使用近似播放时钟）。主播放器暂未出帧时不伪造预览。
- 相邻视频分阶段准备，在当前画面就绪后先准备下一页，再准备上一页。仍需首帧就绪才能滑入，翻页不重建已准备的播放器。
- 备用缩略图提取器限制在 4 MiB 内存；交互路径不启动 VLC 软件取帧，慢取帧自动降频，停止使用后释放资源，不保存图片文件。

## 自动选择的边界

默认仍为 Media3。明确格式不支持且 VLC 已实际出帧的文件可以记住兼容路径；一般 IO、权限和资源不足不永久记为格式不兼容。

仅在目标帧时间戳与新纹理都有证据时记录 Media3 定位耗时。多次慢定位可在下次自然打开时触发一次 VLC 试用，拖动中不会为了比较性能而切换引擎。VLC 失败设冷却并最多回退一次，避免循环重建。

本版没有可靠的 VLC 目标帧时间戳对比，因此该试用不是“已测出并记住最快引擎”。不会以播放时钟变化代替实际出帧证据，也不承诺所有视频零等待。不同编码、关键帧间隔与设备仍会影响精确定位。

记录仅在本机，最多 64 项，以文件身份、大小、修改时间、系统和引擎版本区分；退出页面时写入，不逐帧写盘。不在媒体库刷新时扫描全库码流。

## 分析与验证

REA 检查用户提供的 VLC 3.7.2 安装包，确认其进度条“拖动 fast、松手 precise”调用链；JNI 和核心 `input-fast-seek` 参数另用共享 Ghidra 核对。映序 2.1.0 原实现仅松手执行主播放器精确定位，并非每个移动事件都重复 seek。

本机分析材料位于 `dist/analysis/vlc-20261101`，原始 APKS 与反编译证据不进入源码仓库。

自动检查覆盖持续移动期间真实预览、相同粗定位目标的最终精确帧、最新目标优先、取消、暂停与系统打断、片尾、生命周期释放、三窗口复用、单路声音和 VLC 循环。具体运行结果随测试包的 `VERIFICATION.txt` 提供。模拟器结果不代替用户手机及问题视频的体验。

## 构建与安装

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 assembleRelease -PpreviewInstall=true --offline
```
