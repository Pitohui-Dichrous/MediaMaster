# 定位响应验证 · 2.2.0-test.6

本版保留按媒体特征、设备能力、资源状态和实际播放表现选择解码器的策略，没有机型或媒体身份白名单。三项解码设置和精确最终落点不变。

## 改动

- Media3 连续拖动的目标供给间隔从 80ms 缩短至 16ms，移除应用层额外的 180ms 等待。Media3 自身在旧请求等待输出时只保留最新目标，防止无限累积定位任务。
- 保留首次 50ms 短按保护，普通快速点击只发送最终精准请求。屏幕横滑从原始按下时刻计算保护期，识别方向后不再重新等待。
- 预览保留最多 40 个目标；这是数量上限，不是固定时间窗口。复制纹理期间若检测到帧元数据、纹理时间戳或播放器代际变化，就丢弃该次预览，避免将新时间标签贴在旧画面上。
- LibVLC 保留原来的 80ms 供给和一个执行中、一个最新待处理请求。独立的 16ms 对照未获得稳定收益，未纳入本版；未抢占正在解码的原生请求，也未放宽最终落点。

Media3 的内部合并机制可见[官方 1.11.1 实现](https://github.com/androidx/media/blob/1.11.1/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/ExoPlayerImplInternal.java)。更密集的目标供给不等于相同频率的实际解码或显示。

## 测量口径

v2 测试分别记录注入事件时刻、触摸回调入口和回调结束。主要指标从原始 DOWN/UP 计时，包含输入排队与应用处理。旧的处理结束口径仅保留用于追踪历史，不能与新口径混用。

独立点击逐次核对预先确定的目标画面，稳定确认后回溯记录首次稳定匹配；连续拖动分别统计首个画面变化、手势中的画面变化次数和最终精确落点恢复。媒体时钟更新或进度条移动不算画面恢复。

真实媒体只读，画面参考保留在内存中；原生路径使用同表面的独立稳定参考，不具有独立媒体 PTS 真值。合成视频用逐帧条码核对。输出是采样完成时刻的观测上界，不是屏幕呈现时刻或主观感受的精确测量。

## 验证结果

最终 APK 的 SHA-256 为 `f6f613158c602e2ed6a146b93ded5e43fd02448f347f1bd887b85b1ed9230cf6`。匿名数值与每次操作记录见[验证数据](SEEK_RESPONSE_TEST6.json)。

构建、134 项单元测试通过，Lint 为 0 错误、34 警告。设备验收共 25 项：12 组逐次点击、6 组连续拖动、3 项实际屏幕手势，以及 4 组覆盖三项解码设置和播放/暂停状态的 12Hz/10 秒条码压力测试。屏幕手势检查包含实际预览、取消恢复和竖滑不误触，最终画面用条码核对。所有验收均通过并恢复偏好与隔离历史；完整签名及源码提交记录随安装包提供。

## 使用范围

测试使用按格式选择的媒体覆盖样本，包含较难的长 GOP，不是用户全部视频的随机总体调查。不能将样本比例当作全部设备或媒体的成功率，也不能保证所有定位都“零延迟”。长 GOP、参考帧依赖和解码器的输出行为仍会造成尾部延迟。

测试期间隔离引擎学习历史并恢复播放设置；不更改原始媒体。公开记录不包含设备身份、媒体名称、访问地址、提供器标识、原始画面或媒体文件摘要。
