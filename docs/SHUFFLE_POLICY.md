# 随机播放策略

适用版本：2.3.1。首页抽取与随机队列使用同一套近期观看权重，未引入文件名或设备名单。

## 有效观看

同一次播放进入累计实际观看超过 3,000 毫秒，才记录一次。采用单调时钟的观看时间，不使用媒体位置或倍速推进量。暂停、缓冲、定位、翻页及后台时间不计；预加载不计。暂停恢复和自然循环沿用同一次进入，手动切入其他视频或从目录重新进入建立新一次进入。界面重建保留本次累计时间与已计数状态。

## 衰减与概率

近期分数按 `score × 2^(-间隔 / 7天)` 衰减。每次有效观看先衰减再加 1，上限为 63。随机权重为 `1 / sqrt(1 + score)`，范围为 **1/8 至 1**。

对于一次抽取中仍可选的 N 个候选，概率为 `weight / 所有候选权重之和`，每项至少具有均匀概率的 1/8。权重不是最终概率；所有权重相同或都达到下限时，结果都是 `1/N`。当前本轮已访问项与跨轮紧邻重复的排除，以及回看既有路径，不属于新的随机抽取。

每轮按权重无放回排列，完整覆盖当前列表。只保留最近三轮；已预载候选和回看顺序保持稳定，新抽取或新一轮使用更新后的分数。

## 持久化与边界

SQLite 只保存标识摘要、累计次数、最后播放时间、近期分数与参考时间，最多 50,000 条。累计次数饱和于 Long.MAX_VALUE，但不再直接决定权重；近期分数、无效浮点数、时间差溢出均有界处理。

普通权重查询只在内存中计算衰减，不后台轮询或定时写盘。未来参考时间或时钟回拨会一次性重锚，避免永久冻结惩罚。实际观看及必要的异常修复异步写入。

数据库 v1 升至 v2 保留已有累计记录。旧版缺少逐次观看时间和观看时长，只能把有界累计值作为最后播放时的估计，再衰减到升级时刻；该估计只迁移一次。加载失败时不得以零起算的内存值覆盖旧历史，重命名迁移在共同时间合并分数。
