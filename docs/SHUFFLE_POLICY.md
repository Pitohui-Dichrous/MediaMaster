# 随机播放策略

适用范围：开发分支 `codex/feedback-shuffle`（基于正式版 2.3.1）。首页抽取与随机队列使用同一套近期观看和赞踩权重，未引入文件名或设备名单。

## 有效观看

同一次播放进入累计实际观看超过 3,000 毫秒，才记录一次。采用单调时钟的观看时间，不使用媒体位置或倍速推进量。暂停、缓冲、定位、翻页及后台时间不计；预加载不计。暂停恢复和自然循环沿用同一次进入，手动切入其他视频或从目录重新进入建立新一次进入。界面重建保留本次累计时间与已计数状态。

## 衰减与概率

近期分数按 `score × 2^(-间隔 / 7天)` 衰减。每次有效观看先衰减再加 1，上限为 63。基础权重为 `1 / sqrt(1 + score)`，范围为 **1/8 至 1**。

赞踩不是永久选中状态。另存近期有效观看量 `E`、点赞量 `L` 和点踩量 `D`，三者同样按 **7 天半衰期**衰减。每次有效观看令 E 增加 1；每个播放窗口内，一个视频最多保留一份互斥的赞或踩。按钮再次点按取消，切换赞踩会先撤回本窗口的旧贡献；双击只设为点赞，重复双击不叠加。撤销按贡献已经衰减的剩余量计算，不撤销其他窗口的历史反馈。

关闭播放器后重新进入建立新窗口，可以再次贡献赞踩。旋转、模式切换和 Activity 配置重建保留窗口状态；进程结束后恢复播放属于新窗口。窗口选中态仅存在内存，持久化的是已发生的衰减统计。

使用平滑偏好量 `a = (L - D) / (16 + max(E, L + D))`，基础观看权重记为 b：

- `a >= 0`：`weight = b + (1.5 - b) × a`。
- `a < 0`：`weight = b + (b - 1/16) × a`。

分母中的 16 避免一次操作突然大幅改变排序；相对近期观看而言，持续点赞会逐渐抵消观看惩罚，持续点踩会进一步降低权重。反馈占比低、正负抵消或长时间没有操作时，偏好量趋近 0，回到同一时刻的普通观看权重。没有高、中、低档的突然切换，也不累计固定百分比乘数。E 独立于基础分数 63 的上限，避免大量观看后的少数点赞被误认成高反馈比例。

最终权重范围为 **1/16 至 1.5**。对于一次抽取中仍可选的 N 个候选，概率为 `weight / 所有候选权重之和`，每项至少具有均匀概率的 **1/24**。这是权重下限，不是固定的最终百分比；所有权重相同时，结果都是 `1/N`。当前本轮已访问项与跨轮紧邻重复的排除，以及回看既有路径，不属于新的随机抽取。

每轮按权重无放回排列，完整覆盖当前列表。只保留最近三轮；已预载候选和回看顺序保持稳定，新抽取或新一轮使用更新后的分数。

## 持久化与边界

SQLite 只保存标识摘要、累计次数、最近活动时间、近期观看分与参考时间，以及 E/L/D、共同参考时间和二进制尺度，每个视频一条聚合记录，没有逐次操作日志。累计次数饱和于 Long.MAX_VALUE，但不再直接决定权重。相同窗口状态重复提交不写数据库。

**1,000,000 是共同缩放阈值，不是截断上限。** 当表示量变大时，E/L/D 一起缩小，并记录单位 `u = 2^-exponent`。每次新操作增加 u，偏好公式的先验项也改为 `16 × u`；分子与分母按同样比例缩放，跨过阈值不会改变权重。窗口中的可撤销份额保留相应尺度，取消不影响别的窗口。时间衰减只减少历史贡献，不减少新操作代表的单位；历史衰减后可恢复较大单位，保留新操作精度。

指数、无效浮点数及极端时间差均有保护，最终权重仍有限且为正。超过双精度有效位的极端数量下，新增的一票可能无法精确表示；不会为此清空历史或制造负贡献，撤销仅扣除实际加入的份额。本实现不声称在无限次数下逐票精确。

**50,000 是全局热缓存上限，不是磁盘记录上限。** 淘汰缓存只释放内存，不删除仍有效的赞踩或历史。当前播放队列按需异步读取自己的记录快照，主线程从快照懒计算权重；快照只跟随当前队列存活，不把全部历史加载进内存。快照及存活窗口的贡献能继续引用已移出热缓存的记录。冷记录必须先读旧值再合并，不能把缓存未命中当作“从未观看”。读取失败时不会假装得到均匀权重。

不因暂未扫描到、权限变化、存储卡离线或当前赞踩抵消而删除记录。只有近期观看和 E/L/D 已完全没有可表示贡献、累计次数也为零且没有活动窗口引用时，才具备安全清理条件；其它记录保留，SQLite 可复用空闲页。当前版本没有按数量定期删除历史的任务，权重等于 1 本身不构成清理依据。磁盘无法写入时保留旧记录，不通过删除有效历史来换取保存成功；未提交增量在内存中按视频聚合并重试，若存储始终不可写且进程结束，这部分增量可能丢失，不视为已持久化。

普通权重查询只在内存中计算衰减，不后台轮询或定时写盘。未来参考时间或时钟回拨会一次性重锚，避免永久冻结惩罚。实际观看及必要的异常修复异步写入。

数据库 v1 升级保留已有累计记录。旧版缺少逐次观看时间和观看时长，只能把有界累计值作为最后播放时的估计，再衰减到升级时刻；该估计只迁移一次。本开发版使用 v5；v2 的近期观看分保留，初始 E 以已有近期分数保守估算，L/D 从零开始，不伪造历史逐次反馈。兼容未发布 v3 的中立迁移，不延续其固定赞踩状态；v4 的既有聚合按尺度 0 原样迁移。加载失败时不得以零起算的内存值覆盖旧历史。重命名迁移先在共同时间和尺度合并统计，原播放队列持有的旧引用仍可撤销本窗口贡献。

## 重置

目录和播放设置中的重置操作必须确认。确认后清空所有近期观看分数和 E/L/D，使现有候选恢复相同权重；累计观看次数、视频文件及其他设置保留。所有已有窗口的贡献代际失效，不能通过旧的取消操作把已清空的偏好重新加入。数据库事务成功后才报告完成，失败时保留现有权重并报告错误。重置期间的新观看和重命名顺序延后，赞踩暂不接受；重置前未保存的计数先安全落盘，不能覆盖未知旧历史。播放界面重置后保留当前解码器和播放位置，只重新安排后续随机候选。
