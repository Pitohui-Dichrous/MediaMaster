映序 / MediaMaster Android 工程

当前测试版本：2.2.0-test.5，versionCode 22。
最低 Android 8.0（API 26），compileSdk 36，targetSdk 35。
技术：Java 17、原生 Android Views、Media3 1.11.1、LibVLC 3.7.7。
构建：Gradle Wrapper 8.11.1、Android Gradle Plugin 8.9.2。

构建环境

安装 JDK 17 与 Android SDK 36，配置 JAVA_HOME 和 ANDROID_HOME，或使用 Android Studio 打开项目。
工程内的 Gradle Wrapper 固定 Gradle 版本。local.properties、构建缓存和签名密钥不进入仓库。

当前应用使用包名 io.mediamaster.app.preview。构建时保留 -PpreviewInstall=true：

./gradlew assembleRelease -PpreviewInstall=true
./gradlew testDebugUnitTest lintDebug -PpreviewInstall=true

Windows 可使用 gradlew.bat；已准备本机工具的工作区也可使用：

powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 assembleRelease testDebugUnitTest lintDebug -PpreviewInstall=true

脚本优先使用工作区已有的 Java 17、Android SDK 36 和 Gradle 缓存；构建配置不依赖 REA 分析环境。
通用 APK 位于 app/build/outputs/apk/release/app-universal-release.apk，同时生成各 ABI 的 APK。

包名与签名

previewInstall=true 使用当前包名和本机构建环境的调试签名配置；覆盖更新仍必须使用与已安装版本相同的签名密钥。新机器自行生成的调试密钥不能替代原密钥。
不传该参数会构建 io.mediamaster.app：有本地发布签名配置时使用该配置，否则使用调试签名。这是不同的安装身份，不用于覆盖当前应用。
当前包名可与原 1.3.0 并存，不会自动迁移其设置。签名密钥不在仓库中，后续更新必须保留既有包名和密钥；安装关系见 README.md。

代码与验证

app/src/main/java/io/mediamaster/app：界面、媒体索引同步与文件操作。
app/src/main/java/io/mediamaster/app/player：解码选择、定位、播放顺序与竖屏预载。
app/src/test：不依赖设备的策略及逻辑验证。
app/src/androidTest：设备回归；部分用例需要显式提供生成的测试媒体，不能只凭构建成功视为通过。
docs/DECODER_SETTINGS.md：三种解码选项和默认自动选择规则。
docs/LONG_GOP_SEEK.md：长 GOP 定位实现及验证边界。

默认解码按媒体特征、设备能力与资源情况选择路径；适用的 1080p/60fps 长 GOP 视频优先尝试 Media3 硬解，失败后回到本次决策确定的原生备选。显式软解、硬解偏好继续生效。
历史版本验证文档保持原样；当前测试包的验证结果以对应构建记录为准。
